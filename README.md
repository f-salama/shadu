# شَدْوُ — تطبيق الوالدين (نموذج أولي)

نموذج أولي (prototype) لواجهة تطبيق الوالدين ضمن منصة **شَدْوُ**، وهي مشروع تخرج
لعلاج النطق لدى الأطفال (٥-٨ سنوات) الذين يعانون من اضطرابات نطقية، ليتدربوا في
المنزل بين جلساتهم العلاجية. هذا التطبيق مخصص لولي الأمر، ويهدف لإعطاء انطباع
"بوابة عيادة/تطبيق صحي هادئ وموثوق"، وليس تطبيقًا تحفيزيًا/مُلعّبًا كما هو الحال
في تطبيق الطفل المرافق (خارج نطاق هذا المستودع).

الواجهة بالكامل باللغة العربية واتجاه الكتابة من اليمين لليسار (RTL).

## التقنيات المستخدمة

- **React** (تمت تهيئته عبر Vite)
- **React Router** للتنقل بين الشاشات
- **Recharts** للرسم البياني الخاص بنسبة الدقة عبر الوقت
- **CSS عادي** (بدون Tailwind أو أي مكتبة تصميم) مع متغيرات CSS (custom
  properties) لمركزية ألوان الهوية البصرية والقياسات
- خط **IBM Plex Sans Arabic** من Google Fonts

لا يوجد أي اتصال بخادم/قاعدة بيانات حقيقية — كل البيانات مُولَّدة محليًا (انظر
قسم "ما هو حقيقي وما هو وهمي" أدناه).

## التشغيل محليًا

```bash
npm install
npm run dev
```

ثم افتحي الرابط الذي يظهر في الطرفية (عادة `http://localhost:5173`).

للبناء الإنتاجي:

```bash
npm run build
npm run preview
```

## تسجيل الدخول للتجربة

لا يوجد نظام مصادقة حقيقي، لذا:

- في شاشة **تسجيل الدخول**: أدخلي أي بريد إلكتروني/رقم جوال وكلمة مرور (٦ أحرف
  فأكثر) للدخول مباشرة إلى لوحة التقدم مع بيانات طفل تجريبي جاهزة.
- في شاشة **إنشاء حساب**: بعد تعبئة الحقول، ستنتقلين تلقائيًا إلى تدفق الإعداد
  الأولي (بيانات الطفل ثم اختيار الصوت المستهدف) قبل الوصول للوحة التقدم.

## بنية المشروع

```
src/
  components/
    layout/     # الهيكل العام: القائمة الجانبية، الشريط العلوي، الأيقونات
    ui/         # عناصر واجهة عامة قابلة لإعادة الاستخدام (بطاقات، شارات، صورة رمزية...)
    charts/     # الرسم البياني لنسبة الدقة، وتفصيل أنواع الأخطاء
    chatbot/    # نافذة المساعد الذكي العائمة
  context/      # حالة الطفل المشتركة أثناء الجلسة (React Context)
  data/         # بيانات تجريبية ثابتة (mockData.js)
  pages/        # كل شاشة من شاشات التطبيق
  utils/        # مساعدات بسيطة (حفظ حالة الدخول التجريبية في localStorage)
```

## الشاشات المُنجزة

1. تسجيل الدخول / إنشاء حساب
2. إضافة بيانات الطفل (الاسم، العمر، الصورة الرمزية...)
3. اختيار الصوت المستهدف (صوت السين كخيار أساسي، صوت الكاف كخيار ثانوي) بصياغة
   مفهومة لولي الأمر
4. ملف الطفل (عرض وتعديل البيانات)
5. لوحة التقدم (الشاشة الرئيسية بعد الدخول): ملخص، رسم بياني لنسبة الدقة
   (٧/٣٠ يومًا)، تفصيل أنواع الأخطاء، وبطاقات وصول سريع
6. سجل الجلسات: جدول قابل للبحث والتصفية والفرز (٢٠ جلسة تجريبية)
7. النتائج: تفاصيل كل محاولة/كلمة داخل الجلسة، مع أزرار طباعة ومشاركة (شكليّة)
8. الإعدادات: بيانات الحساب، تفضيلات الإشعارات، اللغة، والتذكيرات الذكية

بالإضافة إلى:

- **التمارين المنزلية الموجّهة**: شاشة مستقلة (تصل إليها عبر القائمة الجانبية
  أو بطاقة الوصول السريع في اللوحة) تعرض ٥ تمارين عملية خطوة بخطوة، تختلف حسب
  الصوت المستهدف للطفل.
- **المساعد الذكي**: زر عائم أسفل الشاشة يفتح نافذة محادثة بأسئلة شائعة
  مُجهّزة مسبقًا، مع حقل نصي حر يعطي ردًا افتراضيًا موحّدًا.

## ما هو حقيقي وما هو وهمي (Mocked)

| الجانب | الحالة الحالية | ما يلزم لاحقًا |
|---|---|---|
| تسجيل الدخول/الحساب | شكلي، أي بيانات صحيحة الصيغة تنجح | مصادقة حقيقية (مثال: JWT/OAuth) وربطها بقاعدة بيانات |
| بيانات الطفل والجلسات | بيانات تجريبية مبنية في `src/data/mockData.js` بمولّد عشوائي محدد (seeded) لثباتها بين التحديثات | جلبها من واجهة API حقيقية مرتبطة بتطبيق الطفل |
| الرسوم البيانية | تُبنى من نفس البيانات التجريبية | نفس المصدر، لكن بعد ربط بيانات حقيقية |
| المساعد الذكي | ردود مكتوبة مسبقًا فقط، لا يوجد نموذج ذكاء اصطناعي فعلي | ربطه بخدمة نموذج لغوي مع سياق طبي محكوم |
| زر "طباعة" في النتائج | يستدعي طباعة المتصفح الفعلية (`window.print`) | تصميم قالب PDF مخصص للمشاركة مع الأخصائية |
| زر "مشاركة مع الأخصائية" | شكلي فقط (رسالة تأكيد مؤقتة) | تكامل فعلي (بريد إلكتروني/رابط آمن/API الأخصائية) |
| حفظ الإعدادات | شكلي (رسالة تأكيد مؤقتة)، لا حفظ فعلي | حفظ في قاعدة بيانات المستخدم |
| "تذكّر آخر شاشة" | `localStorage` لحفظ حالتيّ الدخول وإتمام الإعداد الأولي فقط، لأغراض تجربة العرض | جلسات حقيقية من جهة الخادم |
| تعديل ملف الطفل | يُحدّث حالة React في الذاكرة فقط (`ChildContext`)، يُفقد عند تحديث الصفحة | حفظ دائم في قاعدة البيانات |

## قرارات وافتراضات تصميمية

- **التقويم الميلادي بالعربية**: تم فرض `ar-SA-u-ca-gregory` صراحة عند تنسيق
  التواريخ (بدل `ar-SA` الافتراضي الذي يعرض التقويم الهجري في متصفحات كروميوم)
  لتبقى التواريخ متسقة وواضحة لغرض العرض.
- **اتجاه الرسم البياني الزمني**: تم إبقاء محور الرسم البياني لنسبة الدقة
  بترتيب يسار→يمين (من الأقدم إلى الأحدث) داخل حاوية `dir="ltr"` فقط لمنطقة
  الرسم نفسها، بينما كل ما حولها (العناوين، وسيلة الإيضاح، التلميحات) عربي RTL
  بالكامل. هذا هو النمط الشائع في أغلب تطبيقات التحليلات العربية، لأن عكس اتجاه
  الزمن في الرسم البياني نفسه يسبب التباسًا أكبر من إبقائه.
- **تفصيل الأخطاء**: بدل استخدام Recharts لهذا الجزء، تم بناء مخطط أعمدة أفقية
  مخصص بسيط بالكامل بلغة CSS/RTL طبيعية (الأعمدة تنمو من اليمين لليسار)، لأنه
  أوضح من مخطط دائري مع أربع فئات وأسهل لقراءته من اليمين لليسار بشكل طبيعي.
- **"أيام ممارسة متتالية" (Streak)**: هذا مؤشر التزام سريري (Adherence) مطلوب
  صراحة في متطلبات لوحة التقدم، وليس عنصر تحفيز مُلعّبًا (Gamification) — تم
  الإبقاء عليه بصياغة محايدة بعيدة عن مصطلحات "المستويات/النقاط" الخاصة بتطبيق
  الطفل.
- **الصور الرمزية**: أشكال هندسية بسيطة (موجة، ورقة، نجمة، قطرة، هلال، جبل) على
  خلفيات باستيل من هوية شَدْوُ اللونية، بدل الشخصيات الكرتونية، حفاظًا على طابع
  احترافي هادئ يناسب ولي الأمر.
- **تسجيل الدخول مقابل إنشاء حساب**: افتُرض أن "تسجيل الدخول" يمثّل مستخدمًا
  حاليًا لديه طفل مُعرَّف مسبقًا (فينتقل مباشرة للوحة التقدم)، بينما "إنشاء
  حساب" يمثّل مستخدمًا جديدًا يجب أن يمر بتدفق الإعداد الأولي (بيانات الطفل ثم
  اختيار الصوت المستهدف) قبل الوصول للوحة.

## التجاوب مع الشاشات الصغيرة

التصميم مُحسَّن أساسًا للحاسوب المحمول/الجهاز اللوحي، لكن تم اختباره وضبطه على
عرض شاشة الجوال أيضًا: القائمة الجانبية تتحول إلى قائمة منسدلة عبر زر في أعلى
الشاشة، والبطاقات والجداول تتكيف لعمود واحد.

## القيود المعروفة (خارج نطاق هذا النموذج الأولي)

- لا يوجد اتصال فعلي بأي خادم أو قاعدة بيانات أو خدمة مصادقة
- لا يوجد تسجيل صوت أو معالجة صوتية أو ذكاء اصطناعي حقيقي
- لا توجد نسخة إنجليزية (تصميم عربي/RTL فقط في هذه المرحلة)
- تعديلات ملف الطفل والإعدادات لا تُحفظ بعد تحديث الصفحة (لا يوجد تخزين دائم)
